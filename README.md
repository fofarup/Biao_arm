# Biao_arm

基于 STM32F407ZET6、FreeRTOS 和 CAN 总线的三轴机械臂控制工程。

当前电机控制代码按 **ZDT X42S 第二代闭环步进电机的 X 固件协议**实现。工程包含三轴运动学、关节/电机映射、末端 XYZ 逆解、定时点到点位置控制，以及三次贝塞尔末端轨迹控制。

> 上电后主任务初始化机械臂，并在首次底盘动作前等待 OPS9/HW101 的有效数据。`Task/main_task.c` 当前会循环调用底盘相对运动（前进 1000 mm、旋转 180°）；下载或上电前请先核对该流程、急停、限位和供电保护。

## 硬件与工具

- MCU：STM32F407ZET6
- CAN1：`PA11/CAN1_RX`、`PA12/CAN1_TX`
- 系统时钟：168 MHz；APB1 外设时钟：42 MHz
- CAN 收发器：外接 CAN 收发器后连接电机驱动器
- RTOS：FreeRTOS（CMSIS-RTOS2 接口）
- 末端传感器：ICM42688P，使用 STM32 HAL 硬件 I2C1 读取（不是软件模拟 I2C）
- 构建工具：Keil MDK-ARM V5；工程文件为 `MDK-ARM/Biao_arm.uvprojx`
- 配置工具：STM32CubeMX；配置文件为 `Biao_arm.ioc`

## ICM42688 HAL 接口

`BSP/icm42688.c/.h` 使用 `HAL_I2C_Mem_Read/Write` 访问 ICM42688，当前接线和参数为：

| 信号 | STM32F407 | 说明 |
| --- | --- | --- |
| SCL | PB6 / I2C1_SCL | 100 kHz 硬件 I2C |
| SDA | PB7 / I2C1_SDA | 需要外接上拉电阻 |
| INT1 | PB5 / EXTI5 | 下降沿中断；当前仅统计脉冲，采样由任务轮询 |
| CS | 3.3 V | 选择 I2C 模式 |
| AD0 | GND | 7 位地址 `0x68`，HAL 地址 `0xD0` |
| VDD/VDDIO/GND | 3.3 V/3.3 V/GND | 控制板与传感器必须共地 |

驱动初始化会检查 `WHO_AM_I=0x47`，配置 ±4 g、±1000 dps、100 Hz，并在启用传感器后等待稳定。40 cm 连接线应使用规范的 SDA/SCL 上拉和良好地线；若模块 AD0 接到 3.3 V，需要把 `BSP/icm42688.h` 中的地址改为 `0x69`。

`Task/end_level_task.c/.h` 是独立的末端水平任务：启动后完成 ICM42688 初始化和 100 个样本的陀螺零偏校准，之后以 100 Hz 读取数据并用互补滤波计算 roll/pitch。`main_task` 初始化机械臂时会等待 `EndLevelTask_WaitReady()`，传感器未就绪时不进入机械臂动作流程。ID4 的 Roll 速度闭环默认开启（`END_LEVEL_CONTROL_DEFAULT=1`），目标为固定 0°，采用角度 PI 加陀螺仪角速度阻尼；需要临时关闭时调用 `EndLevelTask_SetControlEnabled(false)`。传感器安装零偏通过 `END_LEVEL_ROLL_ZERO_OFFSET_DEG` 设置。

`uartDebugTask` 启动 OPS9（USART3）和 HW101（USART2）的中断接收，分别重试启动失败的通道，并通过 USART1 每 500 ms 输出一行数据，格式类似：

```text
X=0.00,Y=0.00,YAW=0.00,ROLL=0.00
```

其中 `X/Y` 来自 OPS9，`YAW` 来自 HW101，`ROLL` 来自 ICM42688；ID4 水平闭环使用 `ROLL`。

串口终端选择 `115200-8-N-1`，接收控制板 PA9（TX）和公共地即可；PA10（RX）暂未用于本调试输出。输出周期和发送超时在 `Task/uart_debug_task.c` 中设置。

## 电机端配置

电机端参数必须与代码一致，否则电机可能完全不响应：

| 参数 | 当前工程要求 |
| --- | --- |
| 固件协议 | X（不是 Emm） |
| 通信端口 | CAN |
| CAN 波特率 | 500 kbit/s |
| 校验方式 | 固定校验字节 `0x6B` |
| 应答模式 | `Reached` 或 `Both`（必须允许位置到位 `9F`） |
| 电机地址 | 底座 `1`、大臂 `2`、小臂 `3` |

CAN 总线还需要正确连接 `CANH`、`CANL` 和公共地，并按总线拓扑安装终端电阻。若电机仍处于 UART 端口、Emm 固件或其他波特率，X 协议指令不会生效。电机固件切换需要使用厂家上位机/配置工具完成，本工程不会自动升级电机固件。

## CAN 帧格式

`Fun/zdt_can.c` 将一条电机命令拆分成一个或多个 CAN 扩展帧：

- 使用 29 位扩展帧；扩展 ID 为 `((地址 << 8) | 分包序号)`。
- 分包序号从 `0` 开始递增。
- 每帧第 1 个数据字节是功能码，后面最多携带 7 个命令数据字节。
- 命令末尾固定使用 `0x6B`。

当前 CAN1 配置为普通模式，分频系数 `6`、时间段 `BS1=11TQ`、`BS2=2TQ`，对应 500 kbit/s。

底盘 ID5～8 的位置闭环只使用 OPS9 的 XY 和 HW101 的航向，不读取电机状态反馈。底盘启动时向四台驱动器发送周期 `0 ms`，关闭 `35/36/37/3A` 定时回传；CAN 中断会丢弃 ID5～8 仍可能产生的命令回复，不让它们占用机械臂接收队列。机械臂 ID1～4 的 `9F/35/36/37/3A` 接收逻辑保持不变。此方案无法通过 MCU 识别底盘驱动器的堵转、保护和参数错误，需依靠驱动器自身保护、OPS9/HW101 超时停机及硬件急停。

## X 协议接口

`Fun/X_V2.c` 和 `Fun/X_V2.h` 提供以下接口：

| 接口 | 用途 |
| --- | --- |
| `X_V2_Reset_Clog_Pro` | 清除堵转/过流保护状态 |
| `X_V2_En_Control` | 使能或关闭电机 |
| `X_V2_Vel_Control` | 速度控制 |
| `X_V2_Traj_Pos_Control` | 梯形速度位置控制 |
| `X_V2_Stop_Now` | 立即停止 |
| `X_V2_Synchronous_motion` | 执行同步运动 |
| `X_V2_Reset_CurPos_To_Zero` | 将当前位置清零 |
| `X_V2_MultiMotor_Traj_Pos_Control` | 使用 `00 AA` 多电机命令同时启动三轴 |
| `X_V2_MultiMotor_Vel_Control` | 使用一条 `00 AA` 同时更新三轴 F6 速度 |
| `X_V2_Timed_Return_Info` | 配置驱动器定时返回信息 |
| `X_V2_Read_Info` | 一次读取 `35/36/37/3A` 实时信息 |
| `X_V2_Set_Heartbeat` | 临时设置/关闭驱动器通信心跳保护 |

常用功能码如下：

- 清除保护：`0x0E 0x52 0x6B`
- 使能：`0xF3 0xAB state snF 0x6B`
- 速度：`0xF6 direction acceleration speed×10 snF 0x6B`
- 位置：`0xFD direction acceleration deceleration speed×10 position×10 mode snF 0x6B`
- 立即停止：`0xFE 0x98 snF 0x6B`

位置命令中的速度单位为 RPM，位置单位为角度；代码会分别按 `×10` 转换为协议要求的整数格式。

## 末端位置控制

应用层使用以下接口控制末端位置：

```c
ArmMotionStatus status = ArmMotion_MoveToXYZ(x_mm, y_mm, z_mm, time_s);
```

最后一个参数是三轴共同运动时间，单位为秒。该接口按以下顺序工作：

1. 对末端 XYZ 做逆运动学计算，并检查已启用的关节限位。
2. 将关节角映射为三台电机的绝对位置目标，包含减速比、机构耦合和安装方向。
3. 根据每轴运动距离和共同时间解析计算梯形曲线的加速度、减速度和最大速度。
4. 在满足时间和上限的前提下优先选择最低的 `max(A,D)`，不使用 A/D 二维穷举。
5. 三轴参数全部有效后，通过一条 `00 AA` 多电机命令同时启动；任一轴不可达、超限或时间不可实现时不下发运动命令。
6. 成功下发后函数等待参与运动的电机返回 `FD 9F` 到位帧；三轴全部完成后立即返回，不再固定等待 `time_s + 50 ms`。
7. 等待过程中低频读取 `3A` 状态、`36` 实时位置和 `37` 位置误差；检测到堵转/保护或超过预测时间加 1 秒的看门狗期限时，仅停止机械臂 ID1～3 并返回错误，不广播停止 ID4 和底盘。

当前三轴机构安全上限如下。这些值不是驱动器手册允许的最大值：

| 电机 | Amax (RPM/s) | Dmax (RPM/s) | Vmax (RPM) |
| --- | ---: | ---: | ---: |
| 地址1/底座 | 600 | 700 | 2500 |
| 地址2/大臂 | 300 | 400 | 1800 |
| 地址3/小臂 | 400 | 500 | 2500 |

绝对位置控制前，三个关节必须处于机构物理零位，并已在驱动器端设置零点。`ArmMotion_ConfirmZero(..., true)` 只记录软件确认状态，不执行归零或验证实际位置。

## 贝塞尔末端轨迹控制

贝塞尔轨迹接口如下。`P0` 不由调用者传入，而是从最新的三轴 `36` 位置反馈重建：

```c
ArmCartesianPosition p1 = {30.0f, 180.0f, 210.0f};
ArmCartesianPosition p2 = {70.0f, 195.0f, 205.0f};
ArmCartesianPosition p3 = {100.0f, 200.0f, 200.0f};

ArmMotionStatus status = ArmMotion_MoveBezier(&p1, &p2, &p3, 3.0f);
```

`P1`、`P2`、`P3` 都是机械臂基坐标系中的绝对坐标，不是相对 `P0` 的偏移。三次贝塞尔曲线只保证经过 `P0` 和 `P3`；`P1` 决定起始切向，`P2` 决定终止切向，它们通常不是末端实际经过的点。从不同 `P0` 重复使用同一组 `P1/P2`，曲线形状会改变。

轨迹实现流程：

1. 使用三次贝塞尔空间曲线，并用 `s=10u^3-15u^4+6u^5` 做五次时间缩放，使参考轨迹起终速度、加速度均为零。
2. 运动前按整条实际执行网格（至少 201 点）检查固定逆解分支、几何可达性、已启用的 Alpha/Beta/Gamma 限位、底座轴附近 `20 mm` 奇异区、传动映射和单轴中途换向。任一点失败时不发送运动 CAN。
3. 根据电机连续角度关于归一化时间的一阶、二阶变化，直接使用 `V∝1/T`、`A,D∝1/T²` 反算候选时间，不枚举 A/D/V 组合；计算时只使用配置上限的 `85%`。候选时间还会在整数毫秒/`20 ms` 离散执行网格上重新验证，只有验证通过的值才会写入 `minimum_time_s`。
4. 开始前要求三轴收到屏障之后的新 `35/36/3A`，并确认速度均不超过 `0.5 RPM`、驱动器无故障。真实 P0 的完整预检期间会暂停四类定时返回；三台电机必须各收到四个 `11 02` 停止确认。预检结束后重新开启反馈，再次取得新的 `35/36/3A`，且实测起点与预检 P0 的电机角偏差不超过 `1°`，才允许启动。
5. F6 只有一个加速度字段。代码根据本周期是升速还是降速分别应用各轴的 Amax 或 Dmax，并在 `0.1 RPM` 协议量化后再次限制到本周期实际可达范围。
6. 运行中以名义区间积分匹配生成速度，并用 `36` 位置反馈做限幅比例修正；`35/37/3A` 分别监测速度、位置误差和驱动状态。反馈超过 `100 ms`、CAN 收包丢失/错误、任务节拍迟到超过 `5 ms`、驱动报警或跟踪误差过大时立即停止。
7. F6 流式阶段临时使用 `200 ms` 心跳保护。到达参考时间 `T` 时先同步下发零速度，再立即关闭心跳；收到新的 `35` 确认三轴停稳后建立位置屏障，只用屏障后的三轴新 `36` 重新同步位置，最后发送绝对 FD 并等待所有参与轴的 `9F`。

`time_s` 会按 RTOS 时基量化到整数毫秒。它表示贝塞尔参考轨迹到达 `P3` 的时间，不包含开始前等待新反馈以及末尾 FD/`9F` 精确收尾时间；因此阻塞接口的总返回时间通常略大于 `time_s`。若给定时间无法通过连续上限或离散执行网格校验，接口返回 `ARM_MOTION_TIME_UNACHIEVABLE` 且不启动轨迹。`minimum_time_s` 只返回在相同 P0/P1/P2/P3 和配置下已通过整数毫秒/20 ms 离散校验的安全可执行时间；它是不穷举 A/D/V 得到的保守上界，不宣称是数学上的全局最快时间。`max_speed/max_acc/max_dec/final_speed` 指标仍对应用户本次请求的 `time_s`。

还提供 `ArmMotion_StartBezier()`、`ArmMotion_ServiceTrajectory()` 和 `ArmMotion_AbortTrajectory()` 分阶段状态机接口。进入实际 F6 运行后，`ServiceTrajectory()` 必须由同一个任务以不大于 `5 ms` 的间隔调用，不能再由其他任务直接消费 ZDT CAN 接收队列。首次预检在 `StartBezier()` 内同步完成，基于真实 P0 的二次预检在一次 `ServiceTrajectory()` 调用内同步完成；因此这两个预检阶段并非严格的短时非阻塞调用，超长轨迹需要实测计算耗时。预检状态已纳入忙态，`ArmMotion_StopAll()` 会使正在计算的旧启动代次失效，不能在 Stop 后继续启动。

当前轨迹预检已经包含关节限位和底座轴奇异区，但尚未包含大臂/小臂自碰撞包络、机械臂与底座外形碰撞或环境障碍物模型；首次实机曲线必须低速、留净空并准备硬件急停。

## 上电测试流程

`Core/Src/freertos.c` 启动 `main_task` 和独立的 `endLevelTask`；机械臂一次性初始化由 `Task/main_task.c` 执行：

1. 初始化 CAN 接收队列、过滤器和中断。
2. 等待约 2 秒，让电机驱动器完成上电初始化。
3. 软件确认机械零位，然后清除地址 `1/2/3` 的堵转/过流保护状态，并单独清除、使能末端水平轴地址 `4`。
4. 同时使能三台 XYZ 电机并选择正径向逆解分支。
5. 等待 `endLevelTask` 完成 ICM42688 初始化和静止零偏校准；等待超时会进入故障停机。
6. 初始化成功后先将夹爪设为 0°，等待 OPS9/HW101 均有 200 ms 内的有效数据，再循环调用 `ChassisControl_MoveRelativeSequential(0, 1000, 180, 50, 300, 300)`；机械臂 XYZ 示例当前已注释，需要时可通过 `ArmTask_MoveToXYZOrFault(x, y, z, time_s)` 调用。
7. XYZ 逆解或时间不可达错误发生在发令前，可在 Watch 中查看 `main_task_arm_status` 并继续流程。到位 `9F` 超时后会停止 ID1～3，并在系统时基正常时限时约 1.5 秒，通过新 `35/3A/36` 反馈确认停稳、无故障并重建实际起点；恢复成功后下一条 XYZ 可继续执行。恢复结果见 `main_task_arm_recovery_status`。恢复失败时主流程不永久等待，但会跳过后续 XYZ，避免从未知位置盲动；其他 CAN/驱动器故障仍按原停机逻辑处理。贝塞尔底层接口仍保留在 `Fun/arm_motion.c/.h`。

正式控制仍需要真实归零流程、机械限位开关、碰撞包络和硬件急停。软件心跳只能缓解 MCU/通信任务失效，不能代替独立硬件急停。

## 工程结构

- `Core/Src/main.c`：HAL、时钟、GPIO、CAN 和 RTOS 启动
- `Core/Src/can.c`：CAN1 外设和引脚配置
- `Core/Src/freertos.c`：FreeRTOS 各任务入口
- `BSP/icm42688.c/.h`：ICM42688 HAL 硬件 I2C 驱动和原始/物理量读取
- `Fun/zdt_can.c/.h`：CAN 扩展帧分包、发送、接收队列和统计量
- `Fun/X_V2.c/.h`：ZDT X42S X 固件协议命令
- `Fun/arm_kinematics.c/.h`：机械臂正/逆运动学和关节限位
- `Fun/arm_motor_mapping.c/.h`：关节角、电机减速比、耦合、方向和脉冲映射
- `Fun/arm_trajectory.c/.h`：三次贝塞尔曲线和五次时间缩放纯数学模块
- `Fun/arm_motion.c/.h`：点位控制、贝塞尔状态机、反馈诊断和同步 CAN 下发
- `Task/main_task.c/.h`：机械臂一次性初始化、XYZ 动作封装和高层流程
- `Task/end_level_task.c/.h`：ICM42688 采样、姿态融合、零偏校准和可选 ID4 水平任务

## 构建与下载

1. 使用 Keil MDK-ARM 打开 `MDK-ARM/Biao_arm.uvprojx`。
2. 确认 `Fun` 和 `Task` 组中的新增源文件均已加入工程。
3. 执行 Build/Rebuild，确认无编译错误后下载到 STM32F407ZET6。
4. 连接电机和 CAN 总线后复位开发板，观察电机动作及 CAN 应答。

本轮已使用 Keil ARMCC 5.06u7 完整 Rebuild，结果为 `0 Error(s), 0 Warning(s)`。实机下载前仍建议重新编译，并核对生成 HEX 的时间。

## 无动作排查

优先检查以下项目：

1. 电机协议是否为 X，通信端口是否选择 CAN。
2. 电机地址、500 kbit/s 波特率和固定 `0x6B` 校验是否一致。
3. CANH/CANL 是否接反，CAN 收发器是否供电，控制板与驱动器是否共地。
4. 总线两端是否有终端电阻，驱动器是否有报警或急停锁定。
5. 观察 `zdt_can_tx_error_count`、`zdt_can_error_count` 和 `zdt_can_rx_count`：发送错误通常表示总线没有收到 ACK，接收计数为零则应继续检查应答模式和物理链路。

## 安全提示

当前默认会循环尝试底盘相对运动，同时软件确认机械臂零位并使能三台电机；软件确认不代表真实归零。调试时请架空或卸载机械臂，限制运动范围，确认三台驱动器真实零点一致，并保证急停和断电措施可用。当前到位反馈依赖 CAN 通信；CAN 断线时软件停止命令也可能无法送达。正式运行前必须加入限位开关、真实归零、机械碰撞包络、硬件急停和故障复位流程。
